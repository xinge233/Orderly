# RFC-0001 · 模块界面插槽与动效归属

## 状态

- 状态：已接受，S1 冻结候选
- 决策者：guardian
- 生效阶段：S1
- 影响范围：模块契约 `ui` 字段、框架渲染插槽、主题语义变量、动效归属

## 1. 背景

模块只声明“能力是什么”和“它需要在哪个界面位置出现”。模块不得拥有确认弹窗、进度条、撤销按钮，也不得自行定义界面流程。

框架负责根据 `risk` 推导确认与撤销流程，并根据固定插槽渲染界面。为避免 S2 起各模块自行发明 DOM、类名和交互，S1 必须先冻结插槽名称与形状。

## 2. 决定

### 2.1 模块 `ui` 对象

模块契约中的 `ui` 对象固定包含且仅包含三个键：

| 键 | 类型 | 规则 |
|---|---|---|
| `icon` | string | 必须取 `app/docs/UI-SPEC.md` 图标清单中的名称 |
| `entry` | string | 固定为 `sidebar.item` |
| `accent` | string | 只允许 `accent.primary` 或 `accent.secondary` |

`accent` 不得使用色值，不得使用 `danger.action` 或 `warning.action`。危险与警告外观由框架根据 `risk` 推导，不能由模块自行选择。

### 2.2 固定插槽

S1 只开放以下四个插槽：

| 插槽名 | 渲染位置 | 模块提供的数据 | 框架负责 |
|---|---|---|---|
| `sidebar.item` | 侧边栏条目列表 | `icon`、`name`、`accent` | 尺寸、间距、选中态、排序、搜索过滤 |
| `plan.row` | 计划卡片中的步骤行 | 步骤标题、参数摘要、`risk` | 确认流程、布局、危险色、禁用态 |
| `result.summary` | 执行结果区域 | `status`、`changed`、`counts`、`errorCode` | 时间线、文案结构、空状态、无障碍属性 |
| `settings.panel` | 设置弹窗右侧内容区 | `settings` 数组和当前值 | 控件渲染、布局、滚动、校验反馈 |

插槽只声明所需数据的形状，不声明像素尺寸、字体、颜色、阴影、断点或动画曲线。

### 2.3 插槽不可改名

四个插槽名从 S1 冻结起不得重命名、删除或改变语义。需要扩展时只能新增插槽，并按照 `RFC-TEMPLATE.md` 提交新 RFC。

### 2.4 动效归属

- 页面切换、主题切换、设置弹窗开合：框架所有。
- 按钮反馈、条目选中、红点飞行：框架所有；模块只能声明发生了调用，不能定义时长或曲线。
- 卡片内容动画：模块可以声明使用哪一种已登记的轻量效果，但时长、曲线和降级条件必须来自主题/框架变量。
- 系统启用“减少动效”、首屏加载、快速重复触发或目标不在视口时，直接呈现终态。

### 2.5 界面锚点

为 G8 提供稳定标识，框架必须包含以下六个锚点：

```text
[data-o-anchor="sidebar"]
[data-o-anchor="workspace"]
[data-o-anchor="dock"]
[data-o-anchor="settings-trigger"]
[data-o-anchor="settings-dialog"]
[data-o-anchor="theme-toggle"]
```

锚点名属于框架资产，不得由模块修改或重命名。

## 3. 不采用的做法

- 不采用模块自带确认弹窗：会让模块取得担保能力。
- 不采用模块自带颜色值：会破坏主题和危险色语义。
- 不采用模块自有 DOM/类名作为稳定接口：框架无法统一降级与验收。
- 不采用通配式插槽名：会导致各模块无法被机器校验。

## 4. 兼容性与后续变更

本 RFC 第一次发布后，既有插槽名和 `ui` 三键均为兼容性接口。破坏性改动必须：

1. 在 `app/contracts/` 新增 RFC；
2. 提升模块契约的 `version` 规则说明；
3. 更新 Schema、样例、`app/docs/UI-SPEC.md`；
4. 由编排者确认后再交给实现方。
