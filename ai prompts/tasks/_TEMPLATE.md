# 任务卡模板

> 复制本文件为 `tasks/<阶段>-<任务号>.md` 后填写。
> 五段必填，缺任何一段视为无效任务卡，agent 可以拒绝开工。

---

## 任务号

`S<N>-<短名>`，例：`S1-skeleton`、`S2-module-contract-sample`

## 一句话目标

一句话说清"这个任务做完，什么现象会从不存在变成存在"。不要写"完善 XX"，那不是一个可验收的目标。

## owned_paths

本任务允许写入的路径，精确到目录。落在这里面的文件才是你的产物。

```
contracts/
docs/
```

## forbidden

本任务明确禁止触碰的路径与行为。

```
control/           (engineer 独占)
web/               (ui 独占)
AGENTS.md          任何情况下不得修改
新增依赖            默认拒绝
```

## 输入

开工前必须已存在的文件。缺任何一个，先向编排者要，不要自己造。

| 文件 | 为什么需要 |
|---|---|
| `prompts/02-structure-and-contract.md` | 字段定义来源 |
| — | — |

## 交付物

逐项列出，每项都要能在不问你本人的情况下被验证。

| # | 交付物 | 验证方式 |
|---|---|---|
| 1 | `contracts/module.schema.json` | 用非法样例跑一遍，报错能指到字段 |
| 2 | — | — |

## acceptance

可机器检查或可肉眼复现的验收条件。不要写"质量达标"这类无法判定的条件。

- [ ] 条件一
- [ ] 条件二
- [ ] 门禁 `scripts\gate.cmd` 全绿（如已存在）

## handoff_to

做完之后交给谁，以及下一棒需要读哪个文件。

```
下一棒：engineer
需读：contracts/module.schema.json、docs/MODULAR-CONTRACT.md
前提：本任务交接记录中出现"契约已冻结"
```

## open_questions

开工前必须由编排者回答的问题。每条注明"如果不回答，我按什么默认处理"。

1. 问题 → 默认处理方式
