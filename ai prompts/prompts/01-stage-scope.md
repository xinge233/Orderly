# 01 · 阶段范围与验收

> 读者：全体 agent。这份文件回答三个问题：S1 做什么、不做什么、什么算做完。
> 与 `AGENTS.md` 第 0 节冲突时，以 `AGENTS.md` 为准。

---

## 1. 为什么先做骨架

团队的绝大部分代码由 AI 生成，人的真实工作是设计、评审、验收。这个前提改变了工程规范的对象——**规范约束的不再是人，而是喂给 AI 的输入。**

在这个前提下，第一周唯一值得独占资源做的事是：把**目录、契约、门禁**三件事一次性钉死。理由是它们决定了后面每一次 AI 生成的对错能不能被自动发现：

- 目录钉死 → AI 不会各自发明结构，冲突从"文件改名"降级为"路径不存在"
- 契约钉死 → AI 写错字段时编译不过 / 校验不过，而不是靠人眼发现
- 门禁钉死 → "完成"有了唯一判据，不依赖谁的自我评价

反过来，如果骨架期就开始写业务模块，AI 会在三套互不兼容的目录里各写一遍"列目录"，到 S2 合并时只能重写。

**因此 S1 的产出不是"能用的软件"，而是"一个让后面所有 agent 都不会走偏的笼子"。**

---

## 2. 三条边界

### 2.1 只做框架，不做模块

框架 = 调用器 + 担保机制。本阶段连担保机制都只做形状（枚举、校验钩子、空实现），不做真实逻辑。

允许的"框架级"内容：

- 应用能启动，健康检查能返回结构化状态
- 模块注册表能加载 0 个模块并正常启动
- 契约 Schema 能被解析，能拒绝一份非法样例
- 前端能把注册表渲染成侧边栏条目（0 条时显示空状态）

不允许的：任何"读目录""移文件""建待办"的行为。看到 `Files.list`、`File.listFiles`、`readdir` 这类调用进入 `control/`，即为越界。

### 2.2 只做界面骨架，不做真实交互

界面的验收标准是"**看得出整体结构**"，不是"用起来顺手"。

允许用演示数据（`web/mock/registry.json`）把界面填满：侧边栏列出若干条目、设置弹窗里放几个控件、AI 对话栏能收起展开。这些数据必须是**静态的、明确标注为演示数据**的，且不能有任何一条走真实文件读写。

### 2.3 不碰 AI

`ai/` 目录不存在，Python 不存在，模型调用不存在，提示词工程不存在。

前端可以为 AI 对话栏预留输入框与消息区，但**不接任何后端、不发任何请求**。SSE 客户端可以存在，但必须能在连接失败时优雅降级为"未连接"状态而不报错弹窗（因为 S1 根本没有事件源）。

## 3. 跨阶段不做的事（不是本阶段偷懒，而是永久约束）

以下几条即使到了 S3、S4 也不做，别在 `open_questions` 里反复提：

| 不做 | 理由 |
|---|---|
| 内容生成（写说明、写总结、写建议） | 项目红线，见 `00-project-context.md` §2 |
| 界面渲染模型原文 | 一旦自由文本进入渲染层，"不生成内容"的边界就守不住 |
| 模块自带确认弹窗 / 进度条 / 撤销按钮 | 流程由风险推导，模块只声明风险 |
| 模块引入第三方依赖 | 三人团队的版本冲突成本远高于收益 |
| 多用户、账号、鉴权、多租户 | 本机单用户工具 |
| 运行时热插拔模块 | 编译期静态注册，让"新增能力"在合并请求里可见 |

## 5. 界面骨架的最低可验清单

这一节是给 `ui` 的验收表，也是给 `pm` 的检查表。逐条过，不靠印象。

| 编号 | 可验现象 | 不通过的样子 |
|---|---|---|
| U1 | 侧边栏顶部有搜索框，输入字符后条目被过滤 | 搜索框只是装饰，输入无反应 |
| U2 | 侧边栏条目可上下拖拽改变顺序，松手后顺序保持 | 只有 CSS `cursor: grab` |
| U3 | 侧边栏可滚动，条目多于一屏时出现滚动条 | 内容溢出被裁切 |
| U4 | 侧边栏底部有设置按钮，点击弹出设置弹窗 | 按钮无响应 |
| U5 | 设置弹窗右上角 `×` 可关闭，`Esc` 也能关 | 只能刷新页面关闭 |
| U6 | 设置弹窗左侧分类可滚动，右侧随选中项切换内容 | 左右不同步 |
| U7 | 右侧内容区同时存在数值 / 开关 / 选择框三种控件 | 只有一种 |
| U8 | AI 对话栏默认是右下角收起态，悬停展开为底部横条 | 一直展开或一直隐藏 |
| U9 | 演示数据下可触发"红点从对话栏飞向侧边栏条目"的动效 | 静态图片冒充动效 |
| U10 | 切换主题后整站配色变化，且未修改任何样式文件 | 主题切换靠替换 CSS 文件 |
| U11 | 系统设置为"减少动效"时，所有动效跳过，直接呈现终态 | 动效变慢或半途停住 |
| U12 | 注册表为空时，侧边栏显示空状态文案，不白屏不报错 | 页面崩溃或显示 `undefined` |

U11 特别重要：**先到终态，再放过程。** 界面必须先按最终样子渲染出来，动效只是叠加在已经正确的内容上做位移或淡入。禁止"初始 `opacity: 0` 等动画把自己显示出来"——一旦动效被跳过，内容就永远不可见。

## 6. 完成判据

S1 结束的唯一判据是 `AGENTS.md` §9 的八条。这里补两条执行细则：

1. **不许用"局部可跑"结项。** 只能在你自己的机器上跑通、换台机器就挂的骨架，等于没做。干净克隆 + 一条命令启动是硬要求。
2. **不许用"已知问题清单"结项。** 骨架期的问题只有两种处理：当场修掉，或写进交接记录并明确指派给下一阶段。列一个"以后再说"的清单然后宣布完成，不接受。

---

## 7. 允许提问的时机

以下情况必须停下来问编排者，不许自行决定：

- 契约字段与策划书描述冲突（例如策划书说 8 个工具，但字段设计容纳不下）
- 界面草案与实际布局冲突（例如"对话栏在下方"与"右下角"并存）
- 需要新增顶层目录
- 需要新增依赖
- 需要修改 `AGENTS.md` 或任何 `prompts/` 文件

以下情况**不许**停下来问，自行按规范决定并在交接记录里说明即可：

- 具体用什么 CSS 类名、什么 JS 文件拆分粒度
- 空状态文案写什么
- 演示数据放几条
- 单元测试怎么组织
