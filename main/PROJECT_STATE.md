## 已有模块边界

### 版本化公共 API

- `ModuleCatalogResponse` 不再直接包含内部 `ModuleDescriptor`。
- API DTO 独立位于 `api` 包，包含 `contractVersion: "1.0"`、模块摘要和动作描述。
- `ModuleCatalogMapper` 是内部模型到公共 DTO 的唯一映射入口。
- 固定契约样例：`main/contracts/module-catalog.sample.json`。

### 单一动作来源

- `ModuleHandler.actions()` 是动作能力的唯一声明来源，旧 `supports()` 已移除。
- 每个动作包含 ID、显示名称、参数 schema、风险等级、确认要求、幂等性、回滚支持和所需工作区范围。
- `ModuleRegistry` 在启动时冻结模块描述、动作列表和动作索引。
- 重复模块 ID、重复动作 ID、危险动作未要求确认、只读动作声明写权限都会导致启动校验失败。

### 中央执行管线

- `ExecutionPipeline` 是模块执行的唯一受控入口。
- 固定顺序：动作与参数校验 → 计划确认 → 工作区授权 → 快照准备 → 模块执行 → 快照审计 → 失败回滚。
- 中央管线签发绑定请求、模块和动作的一次性 `ExecutionPermit`；模块不能自行构造许可。
- 当前没有 HTTP 执行端点。
- 未知模块、未知动作、非法参数、未确认动作和越界工作区都会在执行前被拒绝。
- `ModuleDispatchService` 只委托中央管线，不持有模块执行旁路。

### 前端生命周期与契约

- 视图契约包含 `render`、`mount`、`unmount`。
- `MainView` 在切换前释放旧视图，使用 AbortSignal、清理回调和切换代次防止资源泄漏。
- 未知视图直接抛错，不再静默降级到占位页。
- 导航标签和面包屑通过 `textContent` 写入；固定 JSON 契约中的动态模块文本也使用 `textContent`。
- 前端解析固定模块目录契约，并能转换出 `sample-empty → lab → 已注册视图` 链路。
- 设置、导航、主题和 CSS 令牌加入自动一致性测试。

### 工具边界

- `positioning.py` 与 `test_positioning.py` 仍是独立代理边界工具，不参与 Maven 构建、应用启动或 Java 接口测试。
- `main/README.md` 已明确工具边界和独立运行方式。
