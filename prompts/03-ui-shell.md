# 03 · 界面骨架规范

> 读者：`ui`（主要）、`guardian`（定义插槽）、`pm`（按 §7 验收）。
> 落盘目标：`docs/UI-SPEC.md`。本文件是母本。

---

## 1. 一句话原则

**框架给色板和尺子，模块给画法，主题给具体配色。**

三者拼在一起时，任何一方都不应该为了另一方改代码。判断一个界面实现是否合格，用一个问题就能测出来：**换一套配色，需要改几个文件？** 答案必须是一个（主题包）。需要改两个的，说明色值漏到了别处。

---

## 2. 三主体布局

```
┌──────────┬────────────────────────────────────────────┐
│          │                                            │
│  侧边栏   │              主界面                        │
│  240px   │           （卡片流 / 空状态）               │
│  可伸缩   │                                            │
│          │                                            │
│ ┌──────┐ │                                            │
│ │搜索框 │ │                                            │
│ ├──────┤ │                                            │
│ │条目  │ │                                            │
│ │条目  │ │                                            │
│ │ ...  │ │                                            │
│ ├──────┤ │                                            │
│ │⚙设置 │ │                              ┌───────────┐ │
│ └──────┘ │                              │ AI 对话栏 │ │
└──────────┴──────────────────────────────┴───────────┘
                                            收起态：胶囊
                                            悬停 → 展开为底部横条
```

三主体的职责边界：

| 主体 | 负责 | 不负责 |
|---|---|---|
| 侧边栏 | 导航、搜索、排序、设置入口 | 显示任何执行状态 |
| 主界面 | 内容呈现、计划卡片、执行时间线 | 发起调用 |
| AI 对话栏 | 输入、计划预览、执行反馈 | 决定流程（流程由风险推导） |

关键约束：**侧边栏不知道有哪些模块。** 它只渲染注册表给它的条目数组。侧边栏里出现任何模块名，都是耦合。

## 3. 外观变量：两层，色值只在一处

样式取值分两层：

| 层 | 写什么 | 放在哪 | 例子 |
|---|---|---|---|
| 原始变量 | 具体色值、具体数值 | 只允许在 `web/themes/` | `--raw-primary: #2E6BE6` |
| 语义变量 | "这个颜色是干什么用的" | 由框架从原始变量推导 | `--accent-primary`、`--danger-action`、`--surface-card` |

**为什么非要两层：** "删除"这个动作必须永远是危险色。如果模块用主色画删除按钮，换一个红色系主色，删除就变得和普通操作一样了。语义层把"用途"和"色值"解耦，换主题时危险色依然危险。

### 3.1 主题包

主题包是一个 JSON 文件，**只写取值，不写结构**：

| 键 | 必填 | 说明 |
|---|---|---|
| `name` | 是 | 主题显示名 |
| `raw` | 是 | 原始变量键值对 |
| `meta` | 否 | 作者、描述等元信息，不参与渲染 |

规则：

- **部分覆盖必须成立。** 一个主题只给主色与副色也必须能跑，其余值由框架从默认主题补齐后再推导语义变量。
- 合并顺序固定：默认主题提供底值 → 主题包覆盖 → 框架推导语义变量 → 写入页面变量。
- 切换时框架只做两件事：把新值写进页面变量、广播一次"主题已变更"。模块不必重渲染，它也拿不到主题文件——从头到尾只认变量。

S1 至少要交两个主题：默认 + 一个最小主题（只覆盖两个键），用来证明部分覆盖真的成立。

### 3.2 语义变量最小集

S1 必须定义这些语义变量，且每个都在默认主题里有值：

| 变量 | 用途 |
|---|---|
| `--accent-primary` | 主操作、选中态 |
| `--accent-secondary` | 次操作 |
| `--danger-action` | 删除类操作的唯一颜色，任何主题下都必须是危险色相 |
| `--warning-action` | 写操作的确认提示 |
| `--surface-page` | 页面底色 |
| `--surface-card` | 卡片底色 |
| `--text-primary` / `--text-secondary` | 两级文字 |
| `--border-subtle` | 分隔线 |
| `--radius-card` | 卡片圆角（圆润化尖角，禁止 0） |
| `--radius-control` | 控件圆角 |
| `--space-1` ~ `--space-6` | 间距刻度，禁止写死像素 |
| `--duration-fast` / `--duration-base` | 动效时长，禁止写死毫秒 |

**门禁检测的就是这张表之外的漏网值。** `web/` 下除 `themes/` 外出现 `#` 开头的十六进制、`rgb(`、`NNNms`、字体名，门禁 G7 直接失败。

## 4. 界面插槽

插槽是框架留给模块的位置。S1 只需要定义名字与形状，不需要任何模块来填。

| 插槽名 | 位置 | 谁填 | 模块提供什么 |
|---|---|---|---|
| `sidebar.item` | 侧边栏条目列表 | 每条一个模块 | 图标、名称、accent 语义色名 |
| `plan.row` | 计划卡片的每一行 | 每个步骤 | 步骤标题、参数摘要、风险档 |
| `result.summary` | 执行结束后的结果区 | 每次任务 | `counts` 的渲染数据，**不是文案** |
| `settings.panel` | 设置弹窗右侧内容区 | 每个模块 | `settings` 数组声明的控件 |

规则：

- 模块**声明**插槽，框架**渲染**插槽。模块不写 DOM 结构，不写样式，不写流程。
- 要新增插槽，先在 `docs/UI-SPEC.md` 登记，再使用。未登记的插槽名，门禁视为未知标识符。
- 插槽名一旦发布不得改名（改名等于破坏所有已存在的模块），只能新增。

## 5. 动效：三档归属

动效按"缺了会怎样"分三档，各归各家：

| 档 | 内容 | 归属 | 模块能否定义 |
|---|---|---|---|
| 系统级 | 页面切换、主题切换过渡、设置弹窗开合 | 框架 | 否 |
| 反馈级 | 按钮按下、条目选中、红点飞行动效 | 框架 + 插槽声明 | **只能声明"用哪种"，不能定义时长与曲线** |
| 内容级 | 卡片内部内容的自定义动画 | 模块 | 是，但必须走主题变量 |

模块只能定义中间一档的一部分。这条限制解决的是最常见的失控：每个模块各写一套按钮反馈，于是同一个"按下"在三个模块里有三种手感。

### 5.1 AI 调用提示动效

从对话栏发射一个小红点，飞向侧边栏上对应的模块条目，到达时模块条目短暂高亮。

要点：

- 红点是**框架画的**，飞行路径由框架根据目标条目的位置计算
- 模块只声明"我被调用了"，不知道红点存在
- 目标条目不在可视区域时（侧边栏滚走了），红点飞向侧边栏边缘并让侧边栏自动滚到该条目
- 动效进行中不得阻塞任何操作

### 5.2 四条例外与"先到终态"

运行时四个条件会让动效被跳过，处理方式统一为**直接呈现终态**，不降速硬播、不排队等待、不弹窗报错：

| 条件 | 处理 |
|---|---|
| 系统设置为"减少动效" | 跳过全部动效 |
| 连续快速触发（1 秒内重复） | 只播最后一次，其余跳过 |
| 目标元素不在视口 | 不播，直接更新状态 |
| 首屏加载（页面刚打开） | 不播入场动效，直接给终态 |

支撑这四条例外的是一条实现铁律：**先到终态，再放过程。**

界面先按最终样子渲染出来，动效只是叠加在已经正确的内容上做位移或淡入。**禁止"初始不可见、等动画把自己显示出来"**——一旦动效被跳过，内容就永远不可见。这条在 S1 就要守住，因为它是后期最容易返工的地方。

## 6. 三个降级用例（S1 只需前两个）

"缺了也能跑"不能只写在文档里，必须能被当场跑出来。固定三条用例，每条都用同一套演示脚本走完"生成计划 → 确认 → 执行 → 撤销"全程：

| 用例 | 验证什么 | S1 是否要跑 |
|---|---|---|
| 主题降级 | 只给两个键的最小主题下，界面依然可读、危险色依然危险 | 是 |
| 动效全关 | 关闭动效后，所有内容立即可见、状态正确 | 是 |
| 模块缺失 | 删掉一个模块文件夹后，其余界面不受影响 | 否（无真实模块） |

前两条是 S1 的门禁项（G8 的一部分），第三条留给 S2。

## 7. `pm` 验收清单（界面部分）

逐条对照 `01-stage-scope.md` §5 的 U1~U12。这里强调三条最容易被糊弄过去的：

1. **U2 拖拽**：必须是真拖拽（顺序在松手后保持），不是 CSS 假手势。
2. **U10 主题切换**：必须通过改变量实现。如果实现方式是"给 `<body>` 加一个 class 然后把色值再写一遍"，视为不通过——那等于把色值写了两遍。
3. **U11 减少动效**：必须真的跳过，而不是把时长改成 1ms。时长 1ms 仍然要等一帧，而且在低端机上会看到闪烁。

另外一条总检：**在 1366×768 与 1920×1080 两个分辨率下，三主体都不重叠、不溢出、不出现横向滚动条。** 这一条不在 U1~U12 里，但不通过就不算做完。
