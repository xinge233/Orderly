# 05 · 协作流程

> 读者：全体。这份文件定义 agent 之间怎么交接、怎么打回、冲突怎么裁。
> 前提：**agent 会话之间没有共享记忆。** 交接记录是唯一的传递通道，不写等于没做。

---

## 1. 五个位置

| 代号 | 位置 | 写不写代码 | 一句话 |
|---|---|---|---|
| `orchestrator` | 主会话 | 不写 | 发任务卡、裁决冲突、执行合并 |
| `guardian` | 契约与文档 | 只写 `contracts/` `docs/` | 定结构、定契约、审 RFC |
| `engineer` | 控制层与脚本 | 写 `control/` `scripts/` | 骨架、注册表、门禁 |
| `ui` | 前端 | 写 `web/` | 三主体界面、主题、动效 |
| `pm` | 审查 | 不写代码 | 查模块化、跑门禁、出验收结论 |

`pm` 是唯一能否决的角色。`guardian` 是唯一能裁结构争议的角色。两者都不写业务代码，这不是浪费，而是**让"不通过"这件事有人负责**。

---

## 2. 一次完整的 S1 流水线

```
① 编排者发卡
   tasks/S1-skeleton.md 已就位。orchestrator 把它拆成三份派发通知：
   → guardian : 出 schema + docs，冻结契约
   → engineer : 等契约冻结后动 control/ scripts/
   → ui       : 等插槽定义后动 web/

② guardian 先行（串行）
   产出：contracts/module.schema.json、registry.json 空形态、
        docs/MODULAR-CONTRACT.md、docs/UI-SPEC.md、一份非法样例
   交接：tasks/S1-guardian.handoff.md，结论必须是"契约已冻结"或"未冻结 + 原因"

③ 并行实现（engineer 与 ui 同时）
   engineer：control/ 骨架 + scripts/gate.cmd
   ui      ：web/ 骨架 + themes/
   交接：tasks/S1-engineer.handoff.md、tasks/S1-ui.handoff.md

④ pm 验收（串行，可否决）
   输出 tasks/S1-pm-review.md，结论只有两种：通过 / 打回（附证据）

⑤ guardian 复核 + 编排者合并
   复核是否有越界改动、是否有人动了 AGENTS.md 或 prompts/
   合并后更新任务卡状态
```

### 时序上的三条硬规则

1. **契约未冻结，不派实现任务。** 这是为了防止实现反向塑形契约——一旦实现先写，契约就会变成"把已有代码抄成 JSON"。
2. **②阶段 engineer 与 ui 互相只读对方目录。** 需要对方配合时，通过 `docs/UI-SPEC.md` 的插槽名沟通，不直接改对方文件。
3. **④阶段打回必须带证据。** 见 §4。

## 3. 交接记录格式

落盘位置：`tasks/<阶段>-<角色>.handoff.md`。**由编排者落盘**，agent 在会话末尾输出这份内容。

必含六段，缺一段视为该阶段未完成：

```markdown
## 1. 我改了什么
逐个文件列出（路径 + 一句话说明改动）。

## 2. 我没改什么（但应该有人管）
发现的越界、遗漏、别人的 bug。只记录，不动手。

## 3. 门禁结果
粘贴 gate 的原始输出（不是"通过了"三个字）。失败项附原因。

## 4. 遗留问题
每条必须带：现象、我已排除的可能、下一步建议给谁。

## 5. 下一步该谁接
明确到角色代号 + 需要读哪个文件。

## 6. 我做的自主决定
规范留给我自行决定、但我做了选择的地方（§5 列出的那类），
每项写"选了什么 + 为什么不选另一个"。
```

第 6 段特别重要。骨架期会有大量"规范没写、我随手定了"的小决定（类名、文件拆分粒度、空状态文案）。不记录，下一轮 agent 会推翻重来，于是同一件事被决定三次。

---

## 4. 打回的规则

`pm` 打回时，必须给出至少一条可执行证据：

| 证据类型 | 例 |
|---|---|
| 门禁输出 | `G6 失败：启动时报告 modules=1` |
| 文件:行 | `web/css/layout.css:88 → 写死 240px 侧边栏宽度` |
| 复现步骤 | 在 1366×768 下打开，侧边栏与主界面重叠 12px |
| 缺失项 | `docs/UI-SPEC.md` 未登记 `result.summary` 插槽 |

**不接受的打回理由**："感觉不太行"、"和我想的不一样"、"再优化一下"。

被打回方只需修被指出的问题，不需要顺手改别的——顺手改是下一轮冲突的主要来源。

## 5. 谁决定什么

这张表的作用是消除"该不该问"的犹豫。

| 事项 | 决定者 | 需不需要问 |
|---|---|---|
| 契约字段、类型、必填性 | guardian | 不问，但要在交接记录里说明 |
| 新增顶层目录 | guardian + 编排者 | 必须问，走 RFC |
| 新增依赖 | 编排者 | 必须问，默认拒绝 |
| 技术栈任何变动 | 编排者 | 必须问，默认拒绝 |
| 包结构、类名、文件拆分粒度 | engineer | 不问 |
| CSS 类名、DOM 结构、JS 模块划分 | ui | 不问 |
| 插槽名与插槽形状 | guardian | 不问，但必须写进 UI-SPEC |
| 动效时长、曲线 | ui | 不问，但只能定义在主题变量里 |
| 空状态文案 | ui | 不问 |
| 演示数据内容与条数 | ui | 不问 |
| 单测组织方式 | engineer | 不问 |
| 门禁某项的具体实现 | engineer | 不问，但改门禁规则本身要 guardian 复核 |
| 是否通过验收 | pm | 这是 pm 的职责 |
| 修改 `AGENTS.md` / `prompts/` | 只有人 | 必须问 |

## 6. 冲突裁决

三种冲突，三种处理：

### 6.1 结构与实现冲突

现象：engineer 说"这个字段没法实现"，guardian 说"契约就是这么定的"。

裁决：**先判断是契约错还是实现错**，由 guardian 做判断，engineer 提供证据（哪一行、为什么不行）。guardian 判定契约有误时，走契约变更流程（改 Schema + 提 version + 更新样例），不允许 engineer 私自绕过。

### 6.2 界面与契约冲突

现象：ui 需要的数据注册表里没有。

裁决：**加插槽，不加字段。** 界面需要什么，先看能不能用现有插槽表达。表达不了，向 guardian 申请新插槽（写进 UI-SPEC），而不是要求模块多发一个字段。理由：插槽是框架资产，字段是契约资产，后者的变更成本高得多。

### 6.3 两个实现方互相阻塞

现象：engineer 等 ui 的节点标识，ui 等 engineer 的接口形状。

裁决：**先定接口，各写各的。** 由编排者拉一次三方短会（写成一个 `tasks/S1-contract-note.md`），把要交换的两三件事写成文字，然后双方各自按文字实现，不再互等。骨架期这类阻塞几乎都源于"没有把约定写下来"。

## 7. 升级路径

```
agent 遇到阻塞
   ├─ 规范里有答案        → 按规范做，记进交接记录第 6 段
   ├─ 规范里没有，但属 §5 表格里的自主决定 → 自己做，记进第 6 段
   ├─ 规范里没有，且牵涉他人 → 写进交接记录第 2 段，交编排者
   └─ 与 AGENTS.md 冲突     → 立即停手，交编排者，不允许"先做了再说"
```

停手不是失败。骨架期最贵的错误是"一个 agent 自作主张改了结构，其他三个 agent 基于旧结构写了一周"。

---

## 8. 并行时的文件冲突预防

S1 按层切，三层互不重叠：

| 层 | 独占者 | 其他人 |
|---|---|---|
| `contracts/` `docs/` | guardian | 只读 |
| `control/` `scripts/` | engineer | 只读 |
| `web/` | ui | 只读 |
| `tasks/` | 编排者（写交接） | 只读 |

三条操作纪律：

1. 开工前 `git status` 确认工作区干净，否则先问
2. 只提交自己 `owned_paths` 内的文件，`git add` 用显式路径，不用 `git add .`
3. 发现别人目录有未提交改动，不要去"顺手整理"

---

## 9. 会话收尾自检

每个 agent 在结束会话前，按顺序回答：

- [ ] 我的改动是否全部在 `owned_paths` 内？
- [ ] 门禁跑了吗？输出贴了吗？
- [ ] 交接记录六段齐了吗？
- [ ] 第 6 段（自主决定）写了吗？
- [ ] 有没有"我知道有问题但没写下来"的地方？写进第 4 段。
- [ ] 下一步该谁接，写清楚了吗？

六条全部回答"是"，这个会话才算结束。少一条，下一轮 agent 就会多花半小时猜你做了什么。
