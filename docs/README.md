# 归序 Orderly · 提示词配置包（S1 框架期）

这是一套**纯提示词与规范文档**，不含任何代码。目标是把"框架骨架"这一阶段的协作方式固定下来：谁做什么、边界在哪、什么算做完、怎么交接。

拿到这套文件后，把它整体放进仓库根目录，让每个 agent 按角色读自己的那一份。

---

## 一、这套文件解决什么问题

| 常见失败 | 这套文件的对应机制 |
|---|---|
| AI 各自发明目录，合并时全是冲突 | `AGENTS.md` §3 顶层只允许 8 个位置，门禁 G1 硬拦 |
| 契约被实现反向塑形，最后没人敢动 | 契约先冻结再派实现任务，顺序写死在流程里 |
| 每个人都说"做完了"，但没人能证明 | 门禁 + `pm` 否决权 + 交接记录六段 |
| 界面和模块互相耦合，换主题要改十几处 | 色值只在 `themes/`，门禁 G7 扫全站 |
| 模块偷偷把"确认弹窗"写进自己界面 | 流程由风险推导，模块只声明风险，`pm` 专项审计 |
| 上一轮 agent 的决定没人知道，下一轮推翻重来 | 交接记录第 6 段强制写"我做的自主决定" |

## 三、怎么用

### 3.1 第一次投放

1. 把这套文件放到仓库根（`AGENTS.md` 必须在根，`prompts/`、`tasks/` 平级）
   - 本 `README.md` 是给人看的说明，投放时请移到 `docs/` 或直接删除——顶层目录白名单（门禁 G1）不允许根目录多出说明文件
2. 人先读一遍 `AGENTS.md` §0 和 §1，确认 S1 的禁止清单是你想要的
3. 按下面的顺序起会话

### 3.2 起会话的顺序

| 顺序 | 投喂什么 | 期望产出 |
|---|---|---|
| 1 | `prompts/roles/contract-guardian.md` 整份 + 一句"读 `tasks/S1-skeleton.md` §3，开始" | schema + 两份 docs + 样例，结论"契约已冻结" |
| 2 | 并行两个会话：`engineer.md` / `ui-engineer.md` | `control/`+`scripts/` / `web/` |
| 3 | `pm.md` 整份 + 一句"读三份交接记录，开始验收" | 验收报告，通过或打回 |
| 4 | 回到 guardian 复核越界，人做最终合并 | 阶段关闭 |

第 2 步能并行的前提是第 1 步真的冻结了契约。跳过顺序会让契约退化成"把已有代码抄成 JSON"。

### 3.3 在 Codex 里怎么用

Codex 没有"喂文件夹"这个动作。它读的是工作目录，靠 `AGENTS.md` 自动加载，其余文件由它按需读取。所以正确用法是：

1. 把这个文件夹当成仓库根（或把内容平铺进你的仓库根）
2. 在它里面启动 `codex`
3. `AGENTS.md` 会被自动读走，其中的 §4.2 委派规则会让它把活分给四个子代理

三种用法，按你的耐心从高到低：

| 方式 | 怎么做 | 适合 |
|---|---|---|
| 真·多代理 | 直接在 `AGENTS.md` 里写的委派规则下工作，Codex 自动 spawn `guardian`/`engineer`/`ui`/`pm` | 想省事，相信模型判断 |
| 精确指定 | 每次说"用 `guardian` 定契约"，或"派 `pm` 跑一遍验收" | 想控制谁在什么时候动手 |
| 纯手工 | 开四个会话，每个会话开头说"完整读取 `prompts/roles/xxx.md` 并按其执行"，靠 `tasks/*.handoff.md` 交接 | 没有 subagent 支持的环境，或想省 token |

三条实操提醒：

- **不要试图一次把 14 个文件全塞进 prompt**。2200 行、接近 3 万 token，而且 `02`/`03` 都讲插槽、`04`/`05` 都讲门禁，全塞会让它在你自己的规范里迷路。`AGENTS.md` §8 已给出分层加载表，按那个来。
- **`pm` 的 read-only 不是硬保证**。Codex 会用父会话的设置覆盖 agent 文件里的 `sandbox_mode`，所以真正的保护是"PM 只提交一份验收报告"这条纪律 + 合并前 `git diff --stat` 看一眼。
- **并行只在一个写 `control/`、一个写 `web/`、一个只读审计时安全**。两个 agent 同时改同一层会互相覆盖，Codex 子代理共享工作区，不会自动给你隔离。

### 3.4 投喂方式

- **单角色**：`prompts/roles/<角色>.md` 整份作为系统提示词，不要在中间裁剪——那些"硬边界"和"停止条件"段落是这套东西的主要价值。
- **主会话（编排者）**：`AGENTS.md` + 当前任务卡即可，不需要读角色文件。编排者的职责是派发、裁决、合并，不写代码。
- **需要上下文时**：角色文件已写明"开工前按顺序读哪些"，让 agent 自己读，不要人肉复制粘贴内容进去。

## 四、四个角色的分工压缩版

| 角色 | 只做 | 只写 | 独有权力 |
|---|---|---|---|
| 契约守门人 | 定目录、定契约、定插槽 | `contracts/` `docs/` | 裁决结构争议、拒绝加字段 |
| 软件工程师 | 控制层骨架、门禁脚本 | `control/` `scripts/` | 改门禁实现（规则需复核） |
| 界面工程师 | 三主体骨架、主题、动效 | `web/` | 定 DOM 与类名 |
| 项目经理 | 模块化审计、跑门禁、出结论 | `tasks/S1-pm-review.md` | **否决合并** |

三条互补关系：

- 守门人管"结构对不对"，pm 管"有没有真按结构做"
- 工程师管"骨架站不站得住"，ui 管"骨架看得见吗"
- 两者都不写对方的目录，只通过 `docs/UI-SPEC.md` 和 `contracts/registry.json` 交换约定

## 五、协作流程压缩版

```
契约冻结 ──┬─→ 工程师（control/ scripts/）──┐
           └─→ 界面（web/）────────────────┴─→ pm 验收 ──→ 守门人复核 ──→ 合并
```

四条不可跳过的时序：

1. 契约未冻结，不派实现任务
2. 实现期两个方向互不写对方目录
3. pm 打回必须带证据（门禁输出 / 文件:行 / 复现步骤 / 缺失项）
4. 每个阶段必须落交接记录，六段齐全，不写等于没做

## 六、我替你做的默认判断

写这套东西时有几处策划书没写死、我按"骨架期最省返工"的方向定了。不同意就改这几处，其余文件会跟着一致：

| # | 判断 | 依据 |
|---|---|---|
| 1 | S1 不做任何真实文件读写，连 `WorkspacePath` 都只留签名 | 骨架期碰磁盘会逼出权限模型，而权限模型是 S3 的事 |
| 2 | 前端无构建、无 npm、无 CDN | 技术栈已冻结为原生三件套；引入构建会让"一条命令启动"变复杂 |
| 3 | 注册表以 **0 模块**启动，而不是塞一个演示模块 | 0 模块能跑才是模块化的最小证明；塞演示模块会掩盖框架对具体模块的隐性依赖 |
| 4 | 界面用 `web/mock/registry.json` 演示数据撑起来 | 要求"体现整体结构"，但明令不涉及功能模块，演示数据是唯一既不越界又能验收的办法 |
| 5 | 契约定为 **12 个字段** | 覆盖 `AGENTS.md` 十条所需的最小集，多加字段三个端都要维护 |
| 6 | 四个插槽（`sidebar.item` / `plan.row` / `result.summary` / `settings.panel`） | 多设计一半用不上，少一个装不下现有界面 |
| 7 | 门禁 8 项，含"反向验证"要求 | 只写检查不验证检查，会得到永远返回通过的校验器 |
| 8 | 角色定为 4 个（守门人 / 工程师 / 界面 / PM） | 按你选的"再加一位契约守门人"；界面单独拆出是因为它要和工程师并行且写入目录完全不重叠 |
| 9 | "对话栏在下方"与"默认右下角"按"同一组件两态"处理 | 收起态胶囊、展开态底部横条，已在 `03-ui-shell.md` §2 与 `00` §4.2 写明 |

## 七、与原 `D:\code\服创赛\app\` 那套的关系

那套是这次之前的版本（`AGENTS.md` + `contracts/` + `docs/` + `tasks/` + `scripts/` + 空的 `control/`）。这套是重写的，主要差异：

| 项 | 旧版 | 本版 |
|---|---|---|
| 阶段划分 | 一次性把 A0~A6 全铺开 | 只做 S1，后续阶段不预设 |
| 契约 | 散在 `RFC-0001` 里描述 | 独立 `module.schema.json`，12 字段表格式定义 |
| 多 agent | 靠 `agents.cmd` + git worktree 驱动 | 靠角色提示词 + 交接记录驱动，不依赖特定工具的 CLI |
| 门禁 | 只有描述 | 8 项编号 + 报错格式 + 反向验证要求 |
| PM 角色 | 无 | 有，且是否决者 |

旧版可当参考，但**不要同时投喂**——两套对目录和契约的描述不一致，会直接让 agent 卡在"到底按哪个"。
