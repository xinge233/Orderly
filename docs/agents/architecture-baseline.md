## 2. 长期产品事实

归序 Orderly 的核心不是生成更多内容，而是让智能体执行真实工作流时保持可控。

五个核心机制：

1. 计划预览：执行前展示目标、步骤、假设、影响和置信度。
2. 风险分级授权：只读自动放行，写入需要确认，删除需要更强确认。
3. 快照与回滚：写操作前保留可恢复状态，支持单步和整单回滚。
4. 执行可视化：通过事件流展示等待、执行、成功、失败和回滚状态。
5. 意图澄清：置信度不足或计划不可验证时转为反问。

长期边界：

- 只处理文件、目录、待办和日程，不做通用助手。
- 只做操作，不生成文章、图片或其他内容。
- 本地优先，文件操作不经过远端服务。
- 物理删除永不出现，删除进入项目回收站。
- 框架提供授权、快照、回滚和审计担保，模块不得绕过。
- 模型只输出结构化计划，不直接接触文件或业务状态。

## 4. 框架与模块边界

### 框架负责

- 模块注册与宿主生命周期
- 风险等级和授权策略
- 计划校验、执行调度和依赖排序
- 快照、回收站、回滚和事件日志
- SSE 或等价状态推送
- 主题变量、统一外观底座和通用降级视图

### 框架禁止

- 实现文件移动、待办创建、日程修改等具体业务
- 直接依赖具体模块实现类
- 为单个模块增加特判分支
- 持有第二套工具定义或绕过契约

### 模块负责

- 本模块的工具契约
- 执行器与逆操作
- 模块自有数据与迁移声明
- 模块自有界面、插槽注册与可选动效
- 删除模块时清理自身全部能力

### 模块禁止

- 自行判定授权或降低风险等级
- 绕过宿主直接访问文件系统或数据库
- 自行定义全局颜色、字体和动效时长
- 修改框架核心规则

## 5. 契约与 AI 边界

未来实现必须满足：

- 计划契约、接口契约和工具总索引来自统一契约来源。
- 合法与非法样例必须同时存在。
- 模型输出先校验，再进入执行层。
- AI 服务只做目标到结构化计划的转换。
- AI 服务不持有文件权限，不直接执行工具。
- 运行提示词与模型参数放在 `ai/` 的未来目录中，凭据不得进入仓库。
- 当前阶段不得创建任何运行提示词、模型配置或 AI 服务。

## 6. 最低可用界面基线

当前不编写 UI。未来实现时，最低可用版本至少体现以下结构：

| 区域 | 最低要求 | 当前表达 |
|---|---|---|
| 主界面 | 计划预览、执行时间线、结果摘要的容器 | 仅作为未来约束 |
| 左侧侧边栏 | 顶部搜索、模块导航占位、底部设置入口、可滚动 | 仅作为未来约束 |
| AI 对话入口 | 右下角默认收起，可展开为输入区域 | 将来只能是静态占位，除非已获准接入 |
| 设置弹窗 | 左侧导航、右侧内容、右上角关闭入口 | 骨架级弹窗，不实现模块设置 |
| 视觉 | 卡片化、圆润、统一间距和语义变量 | 不硬编码颜色、字体、时长 |
| 动效 | 进度与状态变化可感知 | 可关闭，关闭后内容仍完整可见 |

诚实性要求：

- 未实现能力必须显示“占位”“演示结构”或“尚未接入”。
- 不得用静态文本伪装 AI 已响应。
- 不得在 UI 中执行真实文件操作来制造演示效果。
