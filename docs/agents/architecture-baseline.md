## 2. 长期产品事实

归序 Orderly 的核心不是生成更多内容，而是让智能体执行真实工作流时保持可控。

五个核心机制：

1. 计划预览：执行前展示目标、步骤、假设、影响和置信度。
2. 风险分级授权：只读自动放行，写入需要确认，删除需要更强确认。
3. 快照与回滚：写操作前保留可恢复状态，支持单步和整单回滚。
4. 执行可视化：通过事件流展示等待、执行、成功、失败和回滚状态。
5. 意图澄清：置信度不足或计划不可验证时转为反问。

长期边界：

- 只处理文件、目录、待办和日程，不做通用助手。
- 只做操作，不生成文章、图片或其他内容。
- 本地优先，文件操作不经过远端服务。
- 物理删除永不出现，删除进入项目回收站。
- 框架提供授权、快照、回滚和审计担保，模块不得绕过。
- 模型只输出结构化计划，不直接接触文件或业务状态。

## 3. 首版实现结构

首版采用以下可运行结构；未完成能力必须保持诚实标注：

```text
app/
  kernel/                  模块 SPI、契约模型与跨端基础类型
  frontend/                静态本地界面
  host/                    Java 控制服务、授权、调度、快照、事件与 API
Module/
  modules.index             构建脚本自动生成的运行模块清单
  module_fs/                文件能力、契约与逆操作
  module_todo/              待办能力、契约与逆操作
  module_calendar/          日程能力、契约与逆操作
themes/                     主题取值
contracts/                  计划、接口、工具目录、样例与校验
scripts/                    构建、启动、契约校验
docs/                       产品与协作文档
.codex/                     Codex 项目级配置
```

命名规则：

- V7 采用 `Module/` 作为一级目录；不得在未更新本文件前创建 `modules/`。
- 模块目录使用 `module_fs`、`module_todo`、`module_calendar` 等清晰标识。
- 构建脚本自动发现 `Module/module_*`，逐个构建模块 JAR，并重建 `Module/modules.index`；不要求在根 `pom.xml` 或 host `pom.xml` 登记具体模块。
- 具体编译产物由 Maven 管理；不把 `target/` 或本地运行数据提交到仓库。

## 4. 框架与模块边界

### 框架负责

- 模块注册与宿主生命周期
- 风险等级和授权策略
- 计划校验、执行调度和依赖排序
- 快照、回收站、回滚和事件日志
- SSE 或等价状态推送
- 主题变量、统一外观底座和通用降级视图

### 框架禁止

- 实现文件移动、待办创建、日程修改等具体业务
- 直接依赖具体模块实现类
- 为单个模块增加特判分支
- 持有第二套工具定义或绕过契约

### 模块负责

- 本模块的工具契约
- 执行器与逆操作
- 模块自有数据与迁移声明
- 模块自有界面、插槽注册与可选动效
- 删除模块时清理自身全部能力

### 模块禁止

- 自行判定授权或降低风险等级
- 绕过宿主直接访问文件系统或数据库
- 自行定义全局颜色、字体和动效时长
- 修改框架核心规则

### 模块加载与信任边界

- host 不在编译期依赖具体模块，也不把模块打进 host fat JAR。构建脚本只把当前实际模块逐个复制到 `target/orderly-modules/` 运行时目录。
- 宿主启动时按文件名稳定排序扫描该目录，用 `URLClassLoader` 加载外部 JAR；其父加载器共享 kernel SPI。宿主从 `orderly-modules/*.json` 读取契约，并用 `ServiceLoader.load(OrderlyModule.class, loader)` 绑定执行器。
- 模块目录不存在是合法的零模块状态；`/api/modules` 返回空数组。契约与执行器集合不一致、重复模块或重复动作必须阻止启动。
- 模块只加载一次，不支持热加载。ClassLoader 随宿主关闭而关闭，不在运行中替换 JAR。
- 外部模块 JAR 是本地受信任的可执行代码，不是安全沙箱。当前不提供远程插件下载、来源验证、签名校验或权限隔离，只允许用户放入自己信任的模块。

## 5. 契约与 AI 边界

未来实现必须满足：

- 计划契约、接口契约和工具总索引来自统一契约来源。
- 合法与非法样例必须同时存在。
- 模型输出先校验，再进入执行层。
- AI 服务只做目标到结构化计划的转换。
- AI 服务不持有文件权限，不直接执行工具。
- 运行提示词与模型参数放在 `ai/` 的未来目录中，凭据不得进入仓库。
- 首版可使用隔离的本地规则计划器生成结构化计划，但必须明确标注“未连接外部模型”；该类适配器不得持有文件、回收站或状态写入权限。

主题由宿主动态发现：优先扫描配置的 `themes/*.json` 源目录，源目录不存在时才回退 classpath。`/api/themes` 只返回稳定摘要，`/api/themes/{id}` 返回完整令牌；前端不得保存第二套静态主题列表。主题 id 非法、重复或声明多个默认项时必须失败。

## 6. 最低可用界面基线

首版已实现本地静态界面；后续演进而仍须保留以下最低结构：

| 区域 | 最低要求 | 当前表达 |
|---|---|---|
| 主界面 | 计划预览、执行时间线、结果摘要的容器 | 首版必须体现 |
| 左侧侧边栏 | 顶部搜索、模块导航、底部设置入口、可滚动 | 导航只来自 `/api/modules`；无模块时显示空状态 |
| AI 对话入口 | 右下角默认收起，可展开为输入区域 | 当前只连接本地规则计划器，不得伪装外部模型 |
| 设置弹窗 | 左侧导航、右侧内容、右上角关闭入口 | 动态主题与任意数量模块可见性设置 |
| 视觉 | 卡片化、圆润、统一间距和语义变量 | 不硬编码颜色、字体、时长 |
| 动效 | 进度与状态变化可感知 | 可关闭，关闭后内容仍完整可见 |

诚实性要求：

- 未实现能力必须显示“占位”“演示结构”或“尚未接入”。
- 不得用静态文本伪装 AI 已响应。
- 不得在 UI 中执行真实文件操作来制造演示效果。

## 7. 首版实现验收

当前任务通过的最低条件：

- 应用可通过 README 命令构建和启动，并只监听 `127.0.0.1`。
- 计划在用户确认前不产生真实变化；删除必须使用更强确认并进入项目回收站。
- 文件、待办、日程至少各有一个可执行动作，写操作能够逆序回滚。
- 框架不硬编码具体模块业务，工具元数据来自统一契约来源。
- 前端最低结构完整，未完成能力明确标为占位或未接入。
- 测试、构建、启动和 HTTP 烟测均保留真实命令与结果。

## 8. 已知资料风险

- V7 称“顶层只有七个位置”，但其表格直接列出六个顶层路径，并把 `Module/modules.index` 作为索引项；两者存在计数口径差异。本文件按“六个一级目录加一个模块索引”理解和记录。
- V7 正文有时以 `modules` 泛称模块目录，目录表使用 `Module/`。本文件暂以 V7 的目录表为准，后续若改小写需先决策并统一更新。
- 首版本地规则计划器只覆盖演示指令，不代表 V7 要求的自然语言泛化或真实模型能力。
- 首版工作区固定为应用自管沙箱，尚不支持任意个人目录选择。
- 首版计划和快照只保存在进程内存中；审计事件已持久化，但重启后不能继续操作旧计划。
- `Module/modules.index` 已由构建脚本生成，不再是人工同步项。当前首版允许本地外部模块 JAR 执行，但仓库没有远程分发、来源验证、签名校验或插件权限隔离；这些信任机制仍属于后续安全与分发设计。
