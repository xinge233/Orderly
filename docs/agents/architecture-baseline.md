## 2. 长期产品事实

归序 Orderly 的核心不是生成更多内容，而是让智能体执行真实工作流时保持可控。

五个核心机制：

1. 风险分级授权：只读自动放行，写入和删除必须明确确认。
2. 可选计划预览：计划功能启用时，执行前展示目标、步骤、假设、影响和置信度。
3. Action 直执：总体 AI 可以提交结构化 Action 数组，不生成计划，但必须经过同一宿主执行核心。
4. 快照与回滚：写操作前保留可恢复状态，支持失败后的逆序回滚。
5. 执行可视化：通过持久化执行记录和事件流展示等待、执行、成功、失败和回滚状态。

长期边界：

- 只处理文件、目录、待办和日程，不做通用助手。
- 只做操作，不生成文章、图片或其他内容。
- 本地优先，文件操作不经过远端服务。
- 物理删除永不出现，删除进入项目回收站。
- 框架提供授权、快照、回滚和审计担保，模块不得绕过。
- 模型只输出结构化 Action 数组或可选计划，不直接接触文件或业务状态。
- 真实模型接入使用 Python 3.14 + FastAPI + Uvicorn 本地服务调用 OpenAI 兼容 Chat Completions；DeepSeek 模式固定官方 URL 与 API 模型标识 `deepseek-flash`，自定义模式使用 HTTPS Base URL 与 Model。
- API Key 只临时保存在 Python AI 服务进程内，不进入仓库、命令行、日志、响应、浏览器存储或普通配置文件。

## 3. 首版实现结构

首版采用以下可运行结构；未完成能力必须保持诚实标注：

```text
app/
  kernel/                  模块 SPI、契约模型与跨端基础类型
  frontend/                静态本地界面
  host/                    Java 控制服务、授权、调度、快照、事件与 API
  desktop/                 Windows WebView2 显示外壳，不持有业务或文件权限
Module/
  module_system_control/    控制模块：模块启停、排序与设置入口
  module_fs/                文件能力、契约与逆操作
  module_todo/              待办能力、契约与逆操作
  module_calendar/          日程能力、契约与逆操作
themes/                     目录主题包与登记的主题资源
contracts/                  计划、接口、工具目录、样例与校验
ai/                         Python AI 服务、提示词、工具卡、模型接入和评测基线
scripts/                    构建、启动、契约校验
docs/                       产品与协作文档
.codex/                     Codex 项目级配置
```

命名规则：

- V7 采用 `Module/` 作为一级目录；不得在未更新本文件前创建 `modules/`。
- 模块目录使用 `module_fs`、`module_todo`、`module_calendar` 等清晰标识。
- `module_system_control` 是唯一受保护的控制模块，不属于业务模块目录；零业务模块仍要求该系统模块存在。
- `module_system_` 是宿主内置受保护模块的保留前缀；普通用户模块不得使用。该前缀只提供可读标记，系统身份仍由 `system.protected`、角色、能力和宿主内置准入清单共同决定。
- 构建脚本自动发现 `Module/module_*`，其中系统模块使用 `Module/module_system_*`。前台完整构建默认串行，后台渐进构建默认两路并行且单线程发布模块 JAR；宿主启动时直接扫描运行模块目录并加载 JAR，不维护单独索引，也不要求在根 `pom.xml` 或 host `pom.xml` 登记具体模块。
- 具体编译产物由 Maven 管理；不把 `target/` 或本地运行数据提交到仓库。

## 4. 框架与模块边界

### 框架负责

- 模块注册与宿主生命周期
- 风险等级和授权策略
- 计划校验、执行调度和依赖排序
- 快照、回收站、回滚和事件日志
- SSE 或等价状态推送
- 主题变量、统一外观底座和通用降级视图

### 框架禁止

- 实现文件移动、待办创建、日程修改等具体业务
- 直接依赖具体模块实现类
- 为单个模块增加特判分支
- 持有第二套工具定义或绕过契约

### 模块负责

- 本模块的工具契约、只读查询、本地计划规则和 UI 清单元数据
- 执行器、逆操作与失败恢复
- 模块自有数据与迁移声明
- `orderly-ui/` 内的模块自有界面脚本、样式、可选动效和清单登记的单色图标
- 删除模块时清理自身全部能力

### 模块禁止

- 自行判定授权或降低风险等级
- 绕过宿主直接访问文件系统或数据库
- 自行定义全局颜色、字体和动效时长
- 修改框架核心规则

### 模块加载与信任边界

- host 不在编译期依赖具体模块，也不把模块打进 host fat JAR。构建脚本只把当前实际模块逐个复制到 `target/orderly-modules/` 运行时目录。
- 宿主启动时按文件名稳定排序扫描该目录，用 `URLClassLoader` 加载外部 JAR；其父加载器共享 kernel SPI。宿主从 `orderly-modules/*.json` 读取契约，并用 `ServiceLoader.load(OrderlyModule.class, loader)` 绑定执行器。
- 启动时必须恰好存在一个声明 `system.role=MODULE_CONTROL`、`system.protected=true` 与 `MODULE_GOVERNANCE` 能力的 `module_system_control`。`SYSTEM_SERVICE` 可以登记宿主内置系统服务，但不得声明治理能力；所有系统模块必须使用保留前缀并命中宿主内置准入清单。控制角色缺失或重复、能力不匹配、契约与执行器集合不一致、重复模块或重复动作必须阻止启动；零业务模块仍合法。
- 业务模块与系统模块分开暴露：`GET /api/modules` 只返回业务模块并附带运行态 `enabled`，`GET /api/system-modules` 返回系统模块且恒为启用。系统模块不能通过业务启停、排序或设置接口修改；`module_system_control` 仅可暴露白名单治理查询和动作，实际执行仍由宿主专用治理服务担保。
- 模块查询使用 `GET /api/modules/{moduleId}/query/{queryId}`；模块 UI 只从 JAR 的 `orderly-ui/` 白名单资源读取并提供给 `GET /api/modules/{moduleId}/ui/{asset}`。固定资源为 `module.json` 和清单声明的脚本、样式；模块专属图标必须由同一清单的 `icons` 登记，且只允许 `icons/*.svg|png`。框架不得为具体模块增加查询、端点或视图分支。
- 后台渐进启动默认同时运行 2 个模块 Maven worker，可在系统设置中调整为 1-4。worker 使用隔离可写 Maven 仓库并只产出候选 JAR；状态文件写入、JAR 校验、运行时原子发布和宿主刷新必须由单一父进程串行完成。降低并发不终止已运行 worker，提高并发仅影响后续调度。首轮构建结束后由 `scripts/watch-module-downloads.ps1` 继续监督新下载模块；监督器空闲时不持有仓库构建锁，发现新源码后才调用 `build.ps1 -ModulesOnly` 并请求宿主刷新。
- 运行中可通过固定 GitHub 分发目录安装新的业务模块源码。宿主只接受 `module_*` 且拒绝全部 `module_system_*`，先校验 HTTPS 来源、目录结构、包大小、SHA-256、ZIP 路径、必需文件和普通模块契约，再原子写入 `Module/`。后台监督器完成本地 Maven 构建后，通过 `POST /api/system/modules/refresh` 显式追加新模块；新增模块默认启用并写入治理状态。
- 已加载模块的源码或 JAR 更新、源码删除或 JAR 删除只返回 `RESTART_REQUIRED`，不得替换、更新、热卸载或删除当前运行快照。业务模块删除请求先把源码移入 `.orderly-data/trash/modules`，停用模块并写入 `.orderly-data/module-removals.json`；宿主启动扫描在加载 JAR 前排除待移除模块，重启后再把 JAR 移入同一模块回收站。重启前允许撤销并恢复源码与启用状态，禁止物理删除。刷新单个新增模块失败必须保留旧快照，不允许用新 JAR 替换已有模块。
- 宿主退出通过仅限本机的 `POST /api/system/shutdown` 请求，并要求 `X-Orderly-Action: shutdown`。Action 或计划执行期间拒绝退出；接受后先返回 `STOPPING`，再异步关闭 Java 宿主，由启动脚本清理 AI 服务与后台模块构建器。
- ClassLoader 随宿主关闭而关闭，不在运行中替换 JAR。
- Windows 完整版由 jpackage Java 启动器在宿主健康检查通过后打开 `app/desktop` 中的 WebView2 宿主。该宿主只加载当前 `http://127.0.0.1:<port>/`，不得调用 `AddHostObjectToScript`，不得直接访问工作区或业务状态；关闭窗口必须通过宿主退出接口完成受控清理。
- 外部模块 JAR 是本地受信任的可执行代码，不是安全沙箱。远程模块只允许从配置中的官方 `raw.githubusercontent.com` 分发分支读取，源码包必须与目录 SHA-256 一致；第一版不提供发布者签名、证书链、代码隔离或第三方仓库信任。下载与安装必须由本机用户在模组设置中显式触发，不开放给 AI。

### 模块治理状态

- 宿主在 `.orderly-data/module-governance.json` 单一 JSON 中持久化业务模块 `enabled`、全部运行模块的两套顺序（`sidebarOrder`、`managementOrder`）、`moduleSettings` 以及 Action/Query 的动态 `aiCallableEnabled`；写入使用同目录临时文件加原子替换。
- 新业务模块默认启用，并按契约 `order` 插入 `module_system_control` 之前。`sidebarOrder` 和 `managementOrder` 都包含业务模块与系统模块 ID；旧治理文件中的 `module_control` 顺序 ID 读取时迁移为 `module_system_control`。失效模块 ID 从运行偏好中清理，系统模块可排序但不可停用或写入业务设置。
- 状态文件损坏必须产生包含文件路径和原因的明确启动错误，不得静默回退为空状态。
- 模块设置定义来自模块 JAR 的 `orderly-ui/module.json`。宿主校验字段 key 唯一、默认值、select options 与默认值归属、integer/text 范围，并拒绝未声明字段和错误类型。
- 业务 Action/Query 的 `aiCallableEnabled` 只属于宿主运行治理，默认开启并可由 `module_system_control` 切换；模块契约不得声明静态 AI 权限。`module_system_control` 自身不参与业务接口开关治理，但其固定治理 Action/Query 可进入受控工具卡，动作必须单独执行并复用宿主确认、快照、审计和回滚。动态开关只限制 AI，不阻断模块自身 Query；Query 开关控制已接入的 AI Query。未执行独立 AI 计划引用或执行中的 Action 由宿主标记“使用中”并拒绝关闭；计划确认时原子转换为整次执行占用，结束或失败后释放。旧版计划不参与。
- 模块查询、计划规则、计划生成、计划确认、AI Action 直执和执行前检查都必须尊重业务模块 `enabled`。执行期间禁止停用；回滚不检查 `enabled`，始终允许按快照恢复。
- 开关、设置、两类排序、刷新和打开模块源码目录都必须写入审计事件。打开目录只接受 Windows，只打开配置的 `orderly.module-source-dir`，不接受客户端路径。

## 5. 契约与 AI 边界

未来实现必须满足：

- 计划契约、接口契约和工具总索引来自统一契约来源。
- 合法与非法样例必须同时存在。
- 模型输出先校验，再进入执行层；Action 数组必须由宿主逐项校验参数、风险、确认、输出 schema 和执行顺序。
- Python AI 服务只做目标到结构化 `ACTIONS`、`PLAN`、`QUERY`、`QUESTION` 或 Query 展示 `VIEW` 的转换。
- AI 服务不持有文件权限，不直接执行工具。
- 运行提示词、模型参数、会话和临时凭据管理放在根目录 `ai/`；凭据不得进入仓库。
- 首版可使用隔离的本地规则计划器生成结构化计划，但必须明确标注“未连接外部模型”；该类适配器不得持有文件、回收站或状态写入权限。
- 当前首版真实模型接入由 Python AI 服务承担；Java 通过仅监听 `127.0.0.1`、带每次运行随机 Bearer Token 的 IPC 代理设置与回合请求。Java 不保留第二套模型客户端、提示词或会话。
- Python AI 服务只接收用户目标、结构化 Action/Query 工具卡、短时会话和临时模型配置；不接触文件正文、模块执行器、数据库、回收站、工作区绝对路径或授权状态。
- Java 对 Python 返回结果做最终契约校验。Python 缺失、退出、超时或返回非法结构时，返回明确错误，不得回退 Java AI 或本地规则。
- 独立 AI 计划使用自己的提案 ID、短时状态和确认入口，不复用旧版 `/api/plans`、`PlanService` 或 `planningEnabled`。
- 每个自然语言回合必须携带 `clientRequestId`；宿主按设置代次、会话和请求 ID 去重，重复请求返回首次结果，避免重复执行写入。
- AI 默认返回独立 `PLAN`；意图与参数非常明确时允许直执 `READ_ONLY` 与 `WRITE`。`DELETE` 默认转为 AI 计划确认，只有用户显式开启删除直执后才允许直执，且仍只能进入回收站并保留快照、审计和回滚。
- Action 默认允许总体 AI 调用，用户可通过宿主治理动态关闭；模块契约不声明静态 AI 权限。模块之间不得直接导入或调用，只能通过宿主执行 Action 数组，并使用仅指向前序完成 Action 的结构化输出引用。
- Query 默认允许总体 AI 调用，用户可通过宿主治理动态关闭；关闭只影响 AI Query，不阻断模块自身查询。每回合最多 4 条 Query；模块可用可选 `outputSchema` 和 `display` 声明结果结构与展示建议。Java 校验并执行后，结果同时返回前端，并始终在单条 16 KiB、总计 64 KiB 以内自动回传模型用于受控展示或后续决策，不提供可修改的发送开关；非法 `VIEW` 必须回退本地展示。

主题由宿主在启动时扫描 `orderly.themes-dir` 的直接子目录，不使用 classpath 回退，也不把用户主题打入 fat JAR。每个主题包必须包含 `theme.json`、清单登记的 `tokens.css` 与 `motion.css`，目录名必须与清单 `id` 一致；可选 `assets/` 只提供清单登记的 CSS 与安全静态资源。

`GET /api/themes` 返回 `{items, issues, builtInFallbackActive}`，`GET /api/themes/{id}` 返回完整清单元数据，`GET /api/themes/{id}/assets/{asset}` 提供白名单资源。版本不支持、清单损坏、资源缺失或路径非法只隔离对应主题；重复 id 和多个默认主题仍阻止启动。前端不得保存第二套静态主题列表，回退顺序固定为当前可用主题、可用默认主题、内置安全外观。

主题只支持语义变量、目录内 CSS、关键帧和复杂动效；不得携带 JavaScript，不得侵入模块内部 DOM，也不支持运行中热加载。动效只由程序内 `gentle`、`minimal`、`none` 三档控制，系统 `prefers-reduced-motion` 完全不参与。仅程序的 `motion: none` 档会由框架安全 cascade layer 强制关闭动画、过渡和滚动行为。

## 6. 最低可用界面基线

首版已实现本地静态界面；后续演进而仍须保留以下最低结构：

| 区域 | 最低要求 | 当前表达 |
|---|---|---|
| 主界面 | 模块视图、历史记录；计划启用时增加计划预览、执行时间线和结果摘要 | 计划默认隐藏，历史默认时间线且可切换摘要 |
| 左侧侧边栏 | 顶部搜索、模块导航、底部设置与退出入口、可滚动 | 业务导航来自 `/api/modules`，模块控制入口来自 `/api/system-modules`；固定入口不可排序，动态模块可长按拖动并独立持久化；退出需二次确认并受执行互锁保护；无业务模块时显示空状态 |
| AI 对话入口 | 独立于旧版计划功能，永久显示在右下方并支持拖动 | 未配置模型时临时输入 DeepSeek API Key；配置后发送自然语言目标并显示独立 AI 计划、澄清和执行状态 |
| 设置弹窗 | 左侧导航、右侧内容、右上角关闭入口 | 动态主题、独立 AI 接入，以及任意数量模块的可见性设置 |
| 模组设置 | 系统模块入口、模块启停、排序和接口治理 | 模块行内展开业务与系统治理 Action/Query；业务接口显示 AI 调用开关，系统治理接口只读展示；关闭、模块停用和使用中状态清晰可见 |
| 视觉 | 卡片化、圆润、统一间距和语义变量 | 不硬编码颜色、字体、时长；完整版由 WebView2 原生窗口承载同一界面 |
| 动效 | 进度与状态变化可感知 | 可关闭，关闭后内容仍完整可见 |

桌面侧边栏采用固定 272px 覆盖层，`app-shell` 始终只预留 72px 网格轨道。收起与展开只通过 `clip-path: inset(...)` 从 72px 裁切边界过渡到完整 272px，不改变侧栏宽度或内部主体的布局几何。72px 轨道边缘线由侧栏背景层绘制，展开态清除该背景线并由覆盖层自身右边框标识完整宽度，边线不得覆盖内容或焦点。`<=820px` 移动抽屉使用 `clip-path: none` 和独立 `transform`，不继承桌面裁切规则。

总览卡片由模块 UI 清单生成。用户可通过纵向拖放、按钮和键盘可操作控件调整卡片顺序。侧边栏动态模块可长按拖动，使用独立顺序设置；卡片与侧边栏互不影响。两套顺序均保存在本地设置中，模块目录变化时删除失效 ID 并按契约顺序追加新模块。

诚实性要求：

- 未实现能力必须显示“占位”“演示结构”或“尚未接入”。
- 不得用静态文本伪装 AI 已响应。
- 不得在模型未配置、请求失败或返回非法结构时伪造计划、Action 或成功状态。
- 不得在 UI 中执行真实文件操作来制造演示效果。

## 7. 首版实现验收

当前任务通过的最低条件：

- 应用可通过 README 命令构建和启动，并只监听 `127.0.0.1`。
- 写入和删除在用户明确确认前不产生真实变化；删除进入项目回收站。
- 计划默认隐藏，设置启用后才开放前端入口和计划 API；历史记录始终可用。
- 总体 AI Action 数组顺序执行，首次失败停止并逆序回滚此前完成的 Action。
- 业务模块默认允许 AI 调用，用户通过 `module_system_control` 动态关闭；受保护系统的治理动作必须单独执行，模块间不得直接互调。
- Action 输出引用只能指向此前完成的 Action，并由宿主解析和类型校验。
- 文件、待办、日程至少各有一个可执行动作，写操作能够逆序回滚。
- 框架不硬编码具体模块业务，工具元数据来自统一契约来源。
- 前端最低结构完整，未完成能力明确标为占位或未接入。
- 测试、构建、启动和 HTTP 烟测均保留真实命令与结果。

## 8. 已知资料风险

- V7 的目录表曾把 `Module/modules.index` 作为索引项；当前实现已改为直接扫描 `Module/module_*` 和运行模块 JAR，不再生成或读取该索引文件。
- V7 正文有时以 `modules` 泛称模块目录，目录表使用 `Module/`。本文件暂以 V7 的目录表为准，后续若改小写需先决策并统一更新。
- 首版本地规则计划器只覆盖演示指令，不代表 V7 要求的自然语言泛化或真实模型能力。
- 真实模型连通性需要用户临时提供 API Key；没有可用 Key 时，DeepSeek 实际连通性属于未验证项。
- 源码模式的 Python AI 服务需要 Python 3.14 和 FastAPI/Uvicorn 环境；完整 Windows 发布版使用 PyInstaller onedir 可执行文件并从安装目录启动。两种模式都由启动脚本负责健康检查和双进程清理。
- 模型直执写入属于用户已批准的产品规则扩展；删除直执默认关闭，开启后仍受回收站、快照、审计和回滚约束。
- 首版工作区固定为应用自管沙箱，尚不支持任意个人目录选择。
- WebView2 宿主是唯一 Windows 显示容器；源码开发仍可在浏览器中检查界面。WebView2 Runtime 缺失、固定版本更新和离线性属于发布前必须验证的运行环境项。
- 计划定义仍保存在进程内存中；执行记录、步骤快照、输出和审计事件会持久化。已完成执行可通过 `/api/executions` 跨重启查询和回滚，旧计划对象本身不能在重启后继续确认。
- 当前首版直接发现本地的 `Module/module_*` 源码与运行模块 JAR，不维护模块索引。模块分发包由固定 GitHub 分支提供目录与源码 ZIP；仓库已有 SHA-256、路径边界和受保护前缀校验，但尚未提供发布者签名、证书链或代码隔离，这些信任机制仍属于后续安全设计。
