# Orderly 测试说明与测试记录

本文档是归序 Orderly 测试资产、执行命令、覆盖边界和测试变更的统一记录。它说明“仓库当前有哪些测试、这些测试验证什么、如何运行”，不把测试资产的存在等同于最近一次执行已经通过。

## 1. 记录规则

1. 每次新增测试方法、测试文件、测试脚本、契约测试样例或新的端到端验收场景时，必须在同一变更中更新本文档。
2. 新增记录至少写明日期、测试层级、文件或用例、覆盖行为、执行命令、实际结果和未验证项。
3. 删除、重命名或合并测试时也要记录，不能只减少清单而不说明原因。
4. 结果只能使用 `PASS`、`FAIL`、`NOT RUN` 或 `BLOCKED`。未实际运行的测试必须标记为 `NOT RUN`，不能根据历史结果推断通过。
5. 如果测试命令、前置环境或测试数据发生变化，必须同步更新本文档对应章节。
6. 本文档中的数量是 2026-11-20 的静态源码基线。参数化测试会增加实际运行用例数，因此数量用于盘点测试资产，不作为覆盖率或通过率。

## 3. Java 测试内容

Java 测试以 JUnit 5、Spring Boot 集成测试、AssertJ 和 Mockito 为主。宿主测试大多是接口或服务级集成测试，而不是只测孤立函数。

### 3.1 宿主 API 与执行链

- 验证健康检查、模块目录、契约目录、通用模块查询和模块 UI 白名单接口。
- 验证框架固定的 `/api/files`、`/api/todos`、`/api/calendar` 等业务端点不存在，防止框架重新硬编码具体模块。
- 验证未确认写入返回冲突，未知目标退化为 `QUESTION`，计划功能关闭时计划接口被拒绝但历史仍可读取。
- 验证 AI 删除默认进入独立计划，未确认删除不会产生任何文件变更。
- 验证动态关闭 Action 后 AI 调用返回 `ACTION_AI_DISABLED`，但模块控制等系统来源仍可审计执行。
- 验证 Action 数组按顺序执行、失败即停止、前序完成项逆序回滚、结构化 `$fromAction` 引用可解析。
- 验证文件移动、删除进入项目回收站、待办创建、日程修改和回滚结果。
- 验证失败步骤、快照、执行记录、事件序列和回滚结果能够持久化。
- 验证路径穿越被拒绝，审计事件的来源和序号保持稳定。

### 3.2 AI 网关与 Query

- 验证 Java 只代理 Python AI 服务和临时设置，不在 Java 内保存模型客户端或 API Key。
- 验证 IPC 只允许回环地址、携带每次运行 Bearer Token、拒绝畸形或超大响应，并设置总回合时间预算。
- 验证 Python 服务不可达时明确失败，不回退到 Java 模型或本地规则计划器。
- 验证每回合最多 4 条 Query，Query 结果默认只返回本地，显式同意后才以单条 16 KiB、总计 64 KiB 上限发送模型。
- 验证 Query 续聊不能再次返回 `QUERY`，只能进入允许的最终决策类型。
- 验证 `clientRequestId` 去重、设置代次隔离、相同 ID 不同目标冲突，以及独立 AI 计划使用占用锁和失败释放。
- 验证发给 Python 的工具集只包含启用模块和动态开启的 Action/Query。

### 3.3 模块治理与生命周期

- 验证业务模块目录与系统模块目录分离，`module_control` 唯一、受保护且始终启用。
- 验证模块启停、侧边栏顺序、管理顺序、声明式设置和 Action/Query AI 开关持久化。
- 验证执行中的模块不能停用，停用后模块查询和旧计划被拒绝，但回滚仍可执行。
- 验证独立 AI 计划使用中的接口不能被关闭，执行结束后占用释放。
- 验证缺少控制模块、重复系统角色、重复动作或查询、契约与执行器不一致都会阻止启动。
- 验证零业务模块仍可启动并返回空数组，移除模块后旧查询和 UI 返回 404。
- 验证运行中刷新只追加已构建模块，失败时保留旧快照；已有模块更新或缺失要求重启。
- 验证治理文件损坏会报告明确路径和原因，不能静默回退为空状态。
- 验证关闭宿主需要专用 Header、执行中拒绝关闭、接受后幂等处理并恢复失败场景的执行可用性。

### 3.4 契约、主题与模块

- 验证合法模块契约通过、非法模块契约失败、旧静态 `aiCallable` 字段被拒绝、输出 Schema 受限制。
- 验证重复动作、重复查询、规划规则引用非本模块 Action、契约没有对应执行器时阻止启动。
- 验证模块设置字段的默认值、类型、范围、选项归属和未知字段校验。
- 验证目录主题只扫描直接子目录并稳定排序；损坏主题只隔离自身。
- 验证重复默认主题阻止启动，路径穿越、未登记资源、非 CSS 样式、符号链接和 SVG 不会被当作可执行主题资源。
- `module_calendar` 的模块测试验证初始化幂等、待办和事件的创建、修改、完成、取消及回滚，以及本地 ISO 时间、时区和非法输入处理。

## 4. Python AI 测试内容

Python 测试位于 `ai/tests`，使用 pytest 和 FastAPI 测试客户端。模型供应商调用主要通过可控替身验证请求和错误边界，不会在自动测试中使用真实 API Key。

### 4.1 提示词与解析

- 验证运行提示词包含工具卡、当前时间、计划开关和 Query 约束。
- 验证隐私开关关闭时提示词明确禁止 Query。
- 验证解析器接受代码围栏中的 `ACTIONS`，同时拒绝虚构工具、缺失参数、重复 JSON Key 和错误决策类型的字段。
- 验证 `QUERY` 必须包含 1 至 4 条查询。
- 验证计划关闭时模型返回 `PLAN` 会被修复一次，第二次仍非法则失败。

### 4.2 API、设置与密钥边界

- 验证只有健康接口公开，其余接口缺少或使用错误 Bearer Token 时失败关闭。
- 验证 DeepSeek 固定为官方 URL 和 `deepseek-flash`，自定义模式要求 HTTPS Base URL 与 Model。
- 验证自定义 localhost HTTP 只有显式开发开关才允许。
- 验证设置响应、请求表示、Provider 错误和网络错误都不会回显 API Key 或供应商响应正文。
- 验证设置删除后恢复默认，连接测试使用当前进程内存中的 Key。
- 验证错误响应结构稳定，决策响应不携带无意义的内部空字段。

### 4.3 供应商、会话和 Query 隐私

- 验证 OpenAI 兼容请求的 URL、方法、认证头、请求体和响应内容解析。
- 验证 Chat Completions 路径只追加一次，网络异常和供应商异常经过脱敏。
- 验证相同请求 ID 和相同目标返回首次结果，TTL 到期后失效，相同 ID 不同目标报冲突。
- 验证设置代次变化会使旧请求去重和会话失效，缺失会话 ID 时生成可稳定重放的 ID。
- 验证 Query 结果只有显式开启隐私设置后才能发送，失败 Query 不能携带载荷。
- 验证单条结果超过 16 KiB、总计超过 64 KiB、结果数量超过 4 条都会被拒绝。
- 验证 Query 结果续聊不能再次返回 `QUERY`，并限制可用的最终决策类型。

## 5. 前端与 JS 契约测试内容

前端测试使用 Node 内置测试运行器，主要覆盖纯状态逻辑、API 映射、DOM 适配器和 CSS 文本约束。它们不是完整浏览器自动化测试。

### 5.1 API 与状态模型

- 验证 JSON 请求、结构化错误和本地服务不可达时的错误转换。
- 验证计划 ID、模块、主题、Query、模块 UI、治理接口、关闭 Header 和后台模块构建接口的 URL 与请求形状。
- 验证计划模型信任边界、写操作复选框确认、旧版删除确认、问题不可确认和 Query 展示上限。
- 验证事件去重、排序、旧事件来源推断、执行记录回滚身份和可用性。

### 5.2 AI 对话与设置

- 验证 AI 风险排序取最高风险，执行状态以宿主结果为准，不采用模型自述。
- 验证 Query 结果有数量边界，不凭空生成 Action 或 Plan；宿主失败会显示并通知框架。
- 验证 AI Dock 的可拖动、吸附、视口约束、展开状态、四角位置和窄屏可用性。
- 验证 DeepSeek 与自定义模式、HTTPS 校验、开发期 localhost 例外、隐私开关默认关闭，以及前端从不要求返回 API Key。
- 验证普通设置、宿主托管设置、模块顺序和卡片顺序的存储边界。

### 5.3 模块、主题与布局

- 验证模块 UI 清单、设置 Schema、资源路径、业务/系统目录拆分、禁用模块过滤和后台构建状态。
- 验证 `module_control` 注入边界、接口 AI 开关锁定状态、目录协调和拖放/键盘排序。
- 验证主题只能来自目录，已选主题失效时按“当前主题、默认主题、内置安全外观”回退。
- 验证主题 CSS 替换使用请求代次，慢响应不能覆盖新选择，失败时保留当前主题。
- 验证桌面侧栏 72px 轨道与 272px 裁切覆盖层、移动抽屉、ARIA、`inert`、焦点和 Escape 行为。
- 验证业务样式没有硬编码色值，基础组件没有硬编码动画或过渡，主题和模块遵守语义变量。
- 验证程序 `gentle`、`minimal`、`none` 三档动效，`none` 能完全关闭动画，且仓库不读取系统 `prefers-reduced-motion`。
- 验证 AI Dock、侧栏、设置弹窗在测试覆盖的视口约束下不重叠。

### 5.4 宿主 JS 契约

- 验证模块 UI 合法样例通过归一化，非法资源路径和重复设置 Key 被拒绝。
- 验证学习数据的所有者、只读标记、外部模型声明、图谱边端点、数量一致性。
- 验证 JSON 契约文件拒绝重复对象 Key。

## 6. 系统级与工具级测试

### 6.1 `scripts/doc-gate.ps1`

只读检查关键规则和契约文件、PowerShell 语法与 BOM、上下文工具审计、仓库地图脚本引用、Markdown 冲突标记和本地链接，以及 DOCX OOXML 结构。它不启动 Java、Maven 或 Node。

### 6.2 `scripts/gate.ps1`

完整分支依次执行：

1. 文档门禁和上下文工具拒绝场景。
2. 重点契约合法/非法样例。
3. Python `compileall` 与 pytest。
4. 模块与宿主的 Maven 测试和打包。
5. 前端及所有模块 UI 的 JavaScript 语法检查。
6. 前端 Node 测试、宿主 JS 契约测试和学习数据校验。
7. 禁止模式扫描：物理删除 API、硬编码颜色、固定业务端点、静态主题列表、classpath 主题回退、基础组件硬编码动画、设置面板整体 `aria-live`、主题 JavaScript 和 `!important`。

纯 Markdown/DOCX 变更可以在文档门禁通过后跳过重型测试；代码、脚本、契约、主题、混合变更或不确定变更必须执行完整门禁。

### 6.3 `scripts/modularity.ps1`

使用真实宿主进程和隔离数据目录执行可逆验收：

1. 全业务模块启动，验证系统模块、UI 与通用查询。
2. 移出单个业务模块，验证目录立即变化、被移出接口返回 404、计划目标安全退化。
3. 移出全部业务模块，验证零业务模块仍可启动。
4. 恢复源码并重新构建，确认不是依赖残留 JAR。
5. 临时创建只读模块，验证自动发现、查询、UI 和模块自有计划规则，再验证可逆移出。
6. 临时增加目录主题，验证重启生效、资源可达、无需重建宿主、删除后失效和前端回退。

### 6.4 `scripts/smoke.ps1`

面向已经启动的宿主执行真实 HTTP 烟测：

- 健康状态、JDK 21 和 Python AI 服务可用性。
- 计划开关关闭后的 409 拒绝，以及最终恢复原开关。
- 业务模块、系统模块、模块偏好、模块 UI 和无必填参数查询。
- 目录主题摘要、详情、CSS/静态资源、缓存语义和不泄露宿主路径。
- 可选学习模块的只读负载与引用完整性。
- AI 设置不泄露 API Key。
- 未确认写入拒绝、动态关闭 Action 拒绝。
- 创建目录、列出目录、移入回收站的 3 步 Action 数组和 `$fromAction` 引用。
- 执行记录持久化、列表可见、回滚为 `ROLLED_BACK`。
- 旧计划 API 的关闭/开启行为、未确认执行拒绝和刷新响应结构。

烟测会短暂修改计划开关并在隔离工作区创建测试目录，正常结束后通过执行记录回滚业务变更。

### 6.5 `scripts/test-build-parallel.ps1`

使用隔离的临时仓库和 Maven 包装器验证 8 个场景：

1. 默认串行且共享 Maven 仓库。
2. 显式并发、并发上限和独立 worker 仓库。
3. 模块构建失败时保留原始退出码、stdout、stderr 和旧产物。
4. 宿主阶段失败时恢复上一套模块暂存与宿主 JAR。
5. 严格离线时每次 Maven 调用都带 `-o`。
6. `BootstrapOnly` 只发布控制模块并重建宿主。
7. `ModulesOnly` 只发布指定模块且不重建宿主。
8. 两个外部构建通过同一仓库互斥锁串行等待。

### 6.6 `scripts/verify-offline.ps1`

验证离线源码 ZIP 的 SHA-256、路径白名单、重复项、重解析点、必需包结构、源码/POM/Maven 仓库清单和第三方制品集合，然后在解压目录内以严格离线模式执行完整 Maven 构建与 Java 测试。它不验证 Python 或 Node 的离线安装。

## 8. 当前已知缺口

- 未发现覆盖率工具或覆盖率阈值，无法给出 Java、Python 或 JavaScript 行覆盖率。
- 未发现 `.github` CI 工作流；当前主要依赖维护者在本地执行门禁。
- 前端测试不是完整浏览器 E2E，不能完全替代真实 Chromium 的布局、字体、焦点和视觉效果检查。
